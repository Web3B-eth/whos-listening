# Changelog

What changed in whos-listening, newest first. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Current rules live in [`AGENTS.md`](AGENTS.md) and [`docs/`](docs/), not here.

## [Unreleased]

- README (2026-11-11): the opening no longer says the plugin was built for the Hermes Agent Plugin Hackathon; that stays in the catalog PR text for reviewers.
- Review choices on your word (2026-11-11): keep, keep both, approve and reject no longer always need the memory's number in your message. In a chat that read no outside content they go through on your OK, as saves and forgets do. After outside content, the number still applies at once; without it, Auto-review (one request on the chat's own model, seeing the exact change, the assistant's last message and your newest messages, never the outside content) lets the choice through only on a clear yes, and otherwise the assistant asks for the number. With `review: ask`, or where Auto-review can't run, choices after outside content need the number. A turn with no words of yours still can't make a choice. Choices are logged (which way each went through). Asked for in live testing: the number felt unnecessary next to how other AI apps take an explicit OK.
- Auto-review is logged (2026-11-11): each run, for a held save or a review choice, writes an INFO line to Hermes' log: whether it ran (or why not), on which model, and its verdict. Memory numbers and fixed words only; the model's reason, which can quote a memory, stays out of the log (it still reaches the chat and `/memories pending`).
- Fix (2026-11-11): Auto-review's verdict on a held save was lost when the chat closed before the check answered (Hermes closes the plugin's database at the end of a one-shot `hermes chat -q`); the background check now opens its own connection. Seen in the log as "could not apply the auto-review verdict: ProgrammingError".
- Fix (2026-11-11): the review tool (`whos-listening_review`, added with the duplicate review) counted as outside content, so after the assistant listed your memories every save in that chat waited for Auto-review or your OK. It returns only stored memories, like recall, and no longer counts.
- Duplicate checks are logged (2026-11-11): each save's check writes an INFO line to Hermes' log: the word check's result, whether a judge ran, and the judge's top answers with their odds ("none 0.64, #2 0.33 -> no repeat"), or why it failed. Memory numbers only, never memory text. Asked for in live testing, where a save that passed the check left no trace.
- Review lists say how to choose (2026-11-11): when the review tool lists what's waiting, its reply tells the model to let the user know they answer with the memory's number, with an example that fits the first item ("keep N" for a possible duplicate, "approve N" for a waiting save or forget). Showing all memories tells it to say a memory is named by its number to forget or change it, and that changing one means forgetting it and saving the new version. Asked for during live testing: before, the user learned about the number only when a choice without one was refused.
- Shared gateways save Shared without asking (2026-11-11): on a gateway set to (or defaulting to) Shared, the memory instructions and the remember tool now say this gateway keeps Shared memories only, the tool offers only the `shared` tier, and a save with no tier is Shared. Seen live on Hermes Cloud: the model saved as Private by default, was refused, and asked the user whether to save it as Shared. `/memories add TEXT` saves Shared there too. A save that asks for Private is still refused, and unreadable settings still refuse rather than save Shared.
- Clearer "not running" reasons for the duplicate judge (2026-11-10): `/memories settings` checks for the Venice key first, names the judge actually picked (it said "Jev is anonymized" for Clef), and says when Venice's model list hasn't loaded yet on a fresh gateway (seen on Hermes Cloud right after a restart) instead of calling the model shared or unlisted. The same reason now shows for `model` with a Venice default.
- Duplicate judge (2026-11-10): `duplicate_judge` setting (`clef`, `jev`, `off`). When the word check finds no repeat, one request to Venice's decisions API (Clef, private; or Jev, anonymized) asks which of up to 20 existing memories the save repeats, using the Venice key Hermes already has (read through Hermes' secrets by name). Only answers at 80% or more count, and never across different people (also added to the word check). A Shared judge never sees Private memories. Tested on 42 made-up cases: both caught 20 of 22 duplicates, wrongly skipped 0 of 20 different facts; median 0.48 s (Clef) and 0.26 s (Jev).
- Duplicate judge on the default model (2026-11-10): `duplicate_judge: model` asks Hermes' default model (config.yaml) instead, through PluginLlm, with no Venice key. Private memories go to it only if the gateway, that route and every fallback are Private; an answer from another model is ignored; 20 s limit, then the save goes ahead. Same 42 cases, Grok 4.5 on Venice: 18 of 22 caught, 1 of 20 skipped ("Has a sister named Dana" after "Sister Dana is vegetarian", arguable), median 3.6 s, one 20 s timeout, about 630 tokens a check.
- Duplicate judge: Clef by default, and only where it sees every memory (2026-11-10): with no setting, Clef runs whenever Hermes has a Venice key (otherwise only the word check). Jev and `model` no longer run on Shared memories only: a judge that may not see Private memories doesn't run at all, since it would skip most saves (Private by default) and miss a Shared route rewording a Private memory. `/memories settings` says why the chosen judge isn't running. An unknown value means off.
- Duplicate review (2026-11-10): a Shared memory that says what a Private one says (saved here, or arriving by sync) is now flagged for the user to choose which to keep (it stays in use until then, so a Shared route can't tell); new setting `tier_duplicates` (`ask`, `shared`, `private`). A Private save that repeats a Shared memory is still skipped. Sync arrivals get the near-duplicate checks too: one that rewords a Shared memory is left out here. New `/memories review`, `keep N`, `keep both N`, `review scan` (flags repeats saved earlier, forgets nothing) and `export` (a Markdown file, mode 600), and a `whos-listening_review` tool so the user can do it all in plain language; a choice only applies to a memory number the user's own message in that turn names, and on a Shared route nothing involving a Private memory is shown or changed (not even counted). `duplicate_judge: model` now runs only for saves in a chat on a Private route (never sync or scans). Store schema 5 adds a `duplicate_of` flag.
- Call the tools directly (2026-11-10): the system prompt line and the review tool's description say the whos-listening tools are always listed and should be called by name, not through Hermes' `tool_search`/`tool_call` bridge. Grok 4.5 often sent `whos-listening_review` through the bridge, which answers "not a known tool name" for memory-provider tools (an upstream issue, listed in docs/submission.md). On staging, 6 runs each of "let's review your memories" and "export my memories": before, Grok 4.5 went through the bridge in every run (2-4 failed calls, 18-51 s, the tool reached in 2 of 6); after, it called the tool directly in 10 of 10 (6-12 s). Grok 4.6 called it directly before and after.
- Near-duplicates (2026-11-10): a save that rewords a memory already kept saves nothing new (the reply names the existing memory, or, on a Shared route matching a Private memory, looks like any save). The check is local and deterministic: content words compared with filler and word endings set aside, Jaccard 0.7 and at least two shared words. New `duplicates` setting (`skip` default, `keep`), in Desktop's form and `settings.json`, shown by `/memories settings`. Found in live tests, where a model on a Shared route re-saved a Private memory in other words.
- Venice anonymized models are Shared by default (2026-11-10): Venice passes 63 of its models (Claude, Gemini, some Qwen and GLM variants, Jev) to the company that made them, which sees the content; Who's Listening counted every Venice model as Private. It now reads Venice's public model list (`/api/v1/models?type=all`, no key, at most once a day, kept in `venice-models.json`): Venice's private models stay Private; anonymized ones, unlisted models, and any model before the list is fetched, are Shared. New `venice_anonymized` setting (`shared` default, `private`), in Desktop's form and `settings.json`. A `routes` entry still wins.
- Auto-review by default, fewer needless holds, clearer saves (2026-11-10), from live tests on both gateways: Auto-review (`review: "auto"`) is now the default; a misspelled value or unreadable settings still mean `ask`. Hermes' `skills_list` and `skill_view` no longer count as outside content (on Hermes Cloud a skill loads in most chats, which held every later save). While Auto-review checks a held save, the tool note tells the model you needn't do anything (it used to pass on "approve it with /memories approve N"). A Private save refused on a Shared gateway now tells the model to tell you and offer to save it as Shared (it used to drop it silently, as happened with a bike you mentioned on Hermes Cloud). The model is told to save lasting facts you mention about yourself (what you own, people, preferences, routines, plans, health details) without being asked.
- Hermes Cloud restart (2026-11-10): the README's Desktop install steps now say to restart a Hermes Cloud instance with Stop, then Start, in the Nous Portal. Desktop's Restart gateway only restarts messaging, so chats kept the old tool names after an update until the instance restarted.
- Names (2026-11-10): the tools are now `whos-listening_remember`, `whos-listening_recall` and `whos-listening_forget` (Hermes Desktop shows "Whos-listening Remember" instead of "Wl Remember"; tool names can't hold an apostrophe). Text the plugin writes, for you and for the model, and the README now say "Who's Listening"; the plugin ID, commands, settings and paths stay `whos-listening`. Chats from before the rename aren't supported: the guard only recognizes the new tool names, so start new chats.
- Setup notes and fresher sync (2026-11-10), from a live test on Hermes Cloud: installing from Desktop didn't make whos-listening the memory provider and left Hermes' built-in memory on, so nothing was recalled and nothing said why. `/memories`, `/memories pending` and `/memories settings` now end with a note when whos-listening isn't the memory provider or the built-in memory is on, saying where to change it (a plugin can't change those core settings itself). Every `/memories` command first syncs if one is due, waiting a few seconds at most, so a fresh gateway or a forget made elsewhere shows up. `/memories sync` says "already up to date" and what last changed when a background sync just did the work, and `/memories sync status` shows the last change. The README has install steps for Hermes Desktop and Hermes Cloud, and says when sync really runs.
- Hosted detection that works on Hermes Cloud (2026-11-10): on a real Hermes Cloud instance the gateway counted as Private, because `HERMES_CONFIG_BACKEND` isn't visible to the plugin there. A Hermes on a Fly.io machine (`FLY_APP_NAME` and `FLY_MACHINE_ID`, the signal Hermes itself uses; Hermes Cloud runs on Fly) now counts as hosted too, so its gateway defaults to Shared. `/memories settings` starts with whether this machine counts as hosted, and why.
- Clearer settings form (2026-11-10): every field in Desktop's whos-listening settings now says what it's for with an example, and the sync repository also takes a pasted GitHub link (`https://github.com/you/repo`, `.git` or `git@github.com:` forms), shown as `owner/name`.
- Settings in Desktop, and hosted gateways Shared by default (2026-11-09): `plugin.yaml` declares a `config_schema`, so Hermes Desktop shows whos-listening's settings as a form under Settings → Plugins, for whichever gateway it's connected to (the only way to reach them on Hermes Cloud). whos-listening reads them from Hermes' config (`plugins.entries.whos-listening.settings`) and merges them with `settings.json`, setting by setting; a value set in Hermes wins, and `default` or an empty field means not set. The sync token can be entered there too; Hermes stores it as `WHOS_LISTENING_SYNC_TOKEN`. On a Hermes whose config comes from a remote service (`HERMES_CONFIG_BACKEND=remote`, as on Hermes Cloud) the gateway now counts as Shared unless you set it to Private. New `/memories settings` shows each setting in effect and where it came from. Settings that can't be read, or have the wrong shape, fail safe (everything Shared). The command line uses a copy of the Desktop settings the gateway keeps (`hermes-settings.json`). Lists and `routes` combine both places, Shared winning on a route; a sync repository set in Desktop takes none of `settings.json`'s other sync settings. After an independent review: a `config.yaml` Hermes can't parse, and a damaged or stale-unreadable copy for the command line, fail safe; odd `gateway` values in `settings.json` count as Shared as before.
- Sync between gateways (2026-11-09): gateways share their Shared memories and forgets through one JSON file in a private GitHub repository (Contents API, standard library only). Private memories are never read for sync and never changed by it; pending ones wait until approved; a forget travels as its id and the hash of its words, without text. The last change wins (a forget wins a tie), the same words saved on two gateways stay one line, a Private tombstone is never lifted, and every arrival passes the rule screen (flagged ones wait). Writes are tied to the version read, so two gateways can't overwrite each other. Syncs run in the background when the gateway starts, at most once per `interval` at a turn start, right after a Shared change, and on `/memories sync`; `/memories sync status` reports. New `sync` settings and an optional `WHOS_LISTENING_SYNC_TOKEN`, read only through Hermes' secrets (`optional_env` in `plugin.yaml`). Schema version 4 adds a cross-gateway id per memory and a small sync-state table. A decision made on one gateway alone stays there: forgetting a Private memory or turning down a held memory is never sent, and tombstones record whether their forget travels (a new column in schema 4); an arrival whose words were forgotten that way is kept out. A forget from elsewhere also reaches a held memory. `/memories undo` skips changes that arrived by sync, won't replay your change over one, and can't get stuck. After an independent review: these rules, restore never lifting a Private tombstone, and a sync thread that always clears its running flag. The e2e checks add a second gateway and a fake GitHub server. A change to a memory is always stamped later than its last known change, so a gateway whose clock runs ahead can't undo a forget or restore made after its change (found in the live test against GitHub).
- Webapp note (2026-11-09): the README says that the Hermes Webapp (Desktop in a browser, for example on a phone) counts as the `desktop` platform, so whos-listening can't tell a phone from the computer, and how to serve it safely. Found on local staging with the Webapp over Tailscale Serve.
- Catalog entry ready for the owner's OK (2026-11-09): `docs/catalog-entry.yaml` is pinned to `976b90f` and its description and disclosure cover the three privacy layers, Shared-only chat apps, the recall cap, the dual-kind load and the plugin's own `sys.modules` entry. `docs/submission.md` records the checks done at that commit (validate, doctor, the catalog's structural check and payload scan, the rules read against the code). New `docs/catalog-pr.md` has the upstream PR text. Nothing has been sent upstream.
- Install section (2026-11-09): the README now says how to install for use: install with `--enable`, then `hermes plugins enable whos-listening`, turn off Hermes' built-in memory, restart the gateway and check with `hermes memory status` and `/memories`; plus how to stop using it.
- Three layers, each your call (2026-11-09): a request carries Private memories only if the gateway, the platform and the model route are all Private. New settings: `private_platforms` and `shared_platforms` (with `shared_platforms` winning, as with hosts) and `gateway` (`"private"` by default; `"shared"`, or any other value, makes every request Shared). A Shared gateway, or an unreadable settings file, keeps no Private memories: `wl_remember`, `/memories add` and the CLI refuse Private saves. `/memories` shows Private text on the platforms the settings allow. New README section, Where the backend runs: storage, the gateway's network, the link to Desktop, and Hermes Cloud.
- Chat apps are Shared-only (2026-11-08): on any Hermes platform but `cli`, `tui`, `desktop` and `local` (so Telegram, Signal, Slack, the API server, web chat, cron and subagents), every route counts as Shared, whatever the model, because the app's servers see the replies. Recall, the memory tools, Auto-review and the guard all follow it; the guard uses the `platform` Hermes passes to middleware (empty on the plain CLI, which then goes by the route).
- Testing models and staging (2026-11-08): AI tests and the demo now use Grok 4.5 on Venice and GPT-6.1 Terra on the Nous Portal; cheaper models' occasional bad behavior is not something to engineer around. `AGENTS.md` records the user's local `~/.hermes` install as the approved staging gateway (pin the plugin there, never `hermes update` it); automated tests still use scratch homes.
- Recall cap (2026-11-08): `wl_recall` runs at most 5 times a turn; after that it returns an error. In a real-model test on staging, a cheap model called it 81 times in one turn on a Shared route, where the Private memories it was looking for are never returned.
- `/memories` from the first message (2026-11-08): `plugin.yaml` now says `kind: standalone`, so Hermes' general plugin discovery loads whos-listening at startup and registers `/memories` before any chat. Before, on a fresh gateway (each time Desktop starts one) it was an unknown command until a normal message had built an agent. Hermes now loads the plugin twice (a "dual-kind" plugin), so the route and outside-content books are shared process-wide between the two copies. The e2e checks now enable the plugin and send `/memories` as the first message to a fresh gateway.
- Auto-review and catalog prep (2026-11-08): with `"review": "auto"` in settings, a save held only because of outside content is checked in the background by one request on the chat's own model (via `PluginLlm`, built directly), which sees only the memory and the user's three newest messages; a clear yes applies it, anything else keeps it waiting with the reason. Ported from N of One's memory safety check. `plugin.yaml` no longer lists the memory tools under `provides_tools`, so it declares exactly what `register()` registers, as the catalog requires. Draft catalog entry and a submission checklist in `docs/` (nothing submitted). The e2e checks add Auto-review in real Hermes. After review: Auto-review runs only when Hermes can't retry the check on a less trusted provider (Private route: main provider set and every fallback Private; Shared route: Shared memories only), never for rule-screen holds, at most 3 a turn, with the user's own words only (no bots, other authors or quoted replies; cleared on `/new`), escaped prompt markers, a model check on the reply, and a verdict applied in one transaction only if nothing happened to the memory meanwhile. The catalog draft lists `/memories` and discloses the background check.
- Review and `/memories` (2026-11-08): every save the assistant makes passes a rule screen (links, email addresses, long numbers, instructions to assistants, passwords or keys; ported from N of One), and once a chat has read outside content through any tool but ours, its saves and forgets wait for the user. Waiting memories are never recalled. New `/memories` slash command (list, pending, approve, reject, undo, forget, restore, show, add) and `python -m whos_listening.cli` with the same commands plus owner-only `purge`. Private text is hidden in command replies on chat platforms such as Telegram. Schema version 3 adds forget requests, an event log for Undo and the outside-content flag, which survives a restart. The e2e checks add the planted-file case, the rule screen, `/memories` in a chat and approving from the CLI. After review: restoring or undoing a forget brings a pending memory back pending; the outside-content flag follows compression and `/branch`, and is saved the moment the tool runs; the rule screen checks the text as it will be saved (invisible characters removed); Undo skips purged memories; `/memories add` keeps the text as typed; Private memories are approved only where they can be read; migrations run in one transaction.
- Request guard and tombstones (2026-11-07): an `llm_request` guard checks the real route of every main chat request and, on a Shared route, removes tagged Private memories from every part of it (system prompt, replayed turns, tool results). It never raises: if clean-up fails it removes all memories, and if that fails it sends a notice instead of the conversation. Forgetting a memory now leaves a tombstone (a hash of its words) that stops the same fact being saved again from chat; forgotten text stays on disk until purged, and a forget can be restored. Schema version 2 adds the `tombstones` table. New `e2e/run.py` runs real Hermes against a fake local model server (including a mid-chat switch from a Private to a Shared route, and a `--control` run with the guard off that shows the leak). Shared JSON test vectors in `tests/vectors/`. Test runs now keep Hermes' gateway lock folder inside `.scratch/`. Only the guard records routes now (the `pre_api_request` hook is gone), so recall never believes a route is Private unless the guard is really running; the first turn after Hermes starts carries Shared memories only. On a Shared route the guard also redacts replayed `wl_remember` texts and `wl_recall` queries, catches cut-off tags at either end, and saves never confirm a forgotten Private fact. A `moa` route is always Shared. README Limits now list the Hermes calls that skip middleware (compression, the tool-limit summary, MoA, side calls).
- Store, tiers, recall and tools (2026-11-06): a SQLite store with full-text search under `$HERMES_HOME/whos-listening/`, Private/Shared tiers decided by the route's host (Venice and local addresses Private by default, everything else and anything unknown Shared, with per-provider, per-model and per-host settings), recall that adds only the memories the route may see with Private lines tagged, the `wl_remember` / `wl_recall` / `wl_forget` tools, and provenance on every memory. The request guard is not built yet.
- Hermes 0.23.0 spike (2026-11-05): an `llm_request` middleware from a memory provider works but Hermes sends the request unchanged if it raises; `PluginLlm` runs on the chat's own model from `sync_turn` when built directly (not via `ctx.llm`, and not in host isolation mode); `base_url` is exposed and is the only way to recognise a custom endpoint. Plan adjusted in [`docs/spike.md`](docs/spike.md).
- Agent workflow: `AGENTS.md` (with `CLAUDE.md` importing it), a PR template with a Local handoff, and this changelog. Every change lands as a PR with testing evidence, and only the owner merges.
